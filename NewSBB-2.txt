[2] 결정 사항
-------------
1. 개발 환경 : 참조와 동일하게 JDK 25 (Temurin 25.0.5) / Spring Boot 4.1.2 / Gradle 9.8.2 (Kotlin DSL) / H2.
2. 패키지·루트 프로젝트명은 강사 저장소와 동일하게 com.back / back (build.gradle.kts description 만 NewSBB).
3. 참조 기준 : 강사 저장소 jhs512/p-14172-2 의 038-2 커밋(38강 끝) 상태의 코드 구조를 따른다.
   - REST API(/api/v1/...), RsData 응답, ResponseAspect 로 resultCode 에 맞춘 HTTP 응답코드.
   - 테스트는 @ActiveProfiles("test") + @SpringBootTest + @AutoConfigureMockMvc + @Transactional.
4. 단계 : 요구사항 1~5 를 001~005 로 매긴다. 기능 하나 = 단계 하나 = 커밋 하나.
   단계에 필요한 의존성·설정·엔티티 변경은 그 기능을 처음 쓰는 단계에 넣는다.
5. 프로젝트 생성(Gradle 뼈대, BackApplication, README 머리말, 이 파일)은 기능이 아니므로 번호 없는 "프로젝트 생성" 커밋으로 둔다.
   강사 저장소의 BackApplicationTests(contextLoads)는 요구한 테스트가 아니므로 넣지 않는다.
6. 구현하지 않는 것 : 글·댓글 조회, 글·댓글 수정, 전역 예외 처리 등 요구사항 1~5 밖의 기능.
7. 댓글 작성 API 는 1~38강에 없으므로 같은 형식으로 정한다.
   POST /api/v1/posts/{postId}/comments, 요청 본문 {"content"}, 응답 201 / "201-1" / "%d번 댓글이 작성되었습니다." / 작성된 댓글.
   새 댓글의 id 를 응답에 담기 위해 저장 직후 flush 한다.
8. 글 작성 응답은 038-2 기준대로 data 에 totalCount 와 post 를 함께 담는다.
9. README 개발일지 형식 : 순서는 링크, 작업, 설명. (원인 항목은 이번 저장소에서 쓰지 않는다)
   링크는 단어 "링크"에 해당 커밋 주소를 건다. 작업은 추가/수정/삭제로 나누고 수정은 이전·이후로 적는다.
10. 커밋 메시지 : "번호 + 명사형 제목" 한 줄. 커밋 후 바로 main 에 푸시한다.
